# 安装包签名与首次安装说明

> 记录 buffTerm 桌面安装包的签名现状、系统拦截的机制、可选路线的资格与成本，以及仓库里已经落地的签名接入点。核实时点：2026-11-03。

## 1. 问题是什么

buffTerm 的 Release 产物（`buffTerm_x_universal.dmg` / `buffTerm_x_x64-setup.exe`）目前由 GitHub Actions 构建后直接上传，**没有做 Authenticode 代码签名，也没有做 Apple 公证**。用户第一次下载时看到的是系统拦截提示，而不是安装界面：

- Windows：SmartScreen 蓝屏「Windows 已保护你的电脑」，应用被标记为来自未知发布者。
- macOS：Gatekeeper 提示「无法打开，因为无法验证开发者」；从浏览器或聊天工具下载时还可能提示「已损坏，无法打开」。

对新用户来说，这与「软件有问题」无法区分，是下载转化率的第一道墙。

## 2. 机制：为什么签名不等于立刻免警告

理解这三条才不会把签名当成一次性开关。

1. **Authenticode 只是发布者身份证明**。签名告诉系统「这个文件由某个通过验证的主体签发、且未被篡改」，它本身不提供功能可信度。
2. **SmartScreen 看的是发布者信誉，不是签名有无**。微软按签名主体（CN/O 字段）累计下载量与安装成功率。新发布者即使已正确签名，前期仍会看到「未知发布者」警告，通常需要几周期和数百次安装才逐渐消失；后续版本沿用同一签名主体才能继承这份信誉。因此签名是**必要但不充分**，且必须在稳定的 CI 里对每个版本持续签名，中途换证书主体等于信誉清零。
3. **macOS 是两道独立关卡**：`Developer ID` 证书签名（证明发布者）+ Apple 公证 notarization（Apple 扫描后签发 ticket，`stapler` 钉到 `.app`/`.dmg` 上）。只有公证过的包，离线环境也能被 Gatekeeper 直接放行；Tauri 的 `skipStapling` 会让首次公证（可能耗时数小时）不阻塞构建，正式发版建议保持钉票。

## 3. 可选路线与资格

| 路线 | 2026-11-03 的资格与成本 | 对本项目的判断 |
| --- | --- | --- |
| Azure Artifact Signing（原 Trusted Signing） | 公共信任证书仅面向**美国、加拿大、欧盟、英国的组织**与**美国、加拿大的个人开发者**；中国大陆个人开发者不在范围内。费用按账户计费（基础档约每月数美元级） | ❌ 当前身份不可用，不要按这条准备预算 |
| CA issued OV 代码签名证书（DigiCert / Sectigo / GlobalSign 等） | 任何地区的个人或组织都可购买，需域名/邮箱与身份材料审核；年费量级约数百至上千元人民币 | ✅ 与仓库现有接入点直接兼容（只需两个 Secrets） |
| SignPath Foundation | 面向开源项目免费，由基金会的签名服务代签；需要提交项目申请、通过审核，且发布流程改为把构建产物交给其签名管道 | ✅ 零成本路线，代价是申请与流程改造 |
| 暂不签名，只改进提示 | 0 成本 | 已落地：README 与官网写明放行步骤 |
| Apple Developer Program（macOS 公证） | 99 美元/年，个人可用身份证件在中国大陆注册；Developer ID 证书需再走一次证书申请 | ✅ 唯一能消除 macOS「无法验证开发者」的路线 |

结论：**Windows 走 CA 的 OV 证书或 SignPath 二选一；macOS 走 Apple Developer Program。** 无论哪条，签名动作都放在 CI，私钥只以 Secrets 形式存在，不落仓库。

## 4. 仓库已落地的接入点

`.github/workflows/release.yml` 现在的逻辑：构建前先探测 Secrets，探测结果决定走哪条构建步骤。

- `Detect installer signing setup`：按 `RUNNER_OS` 检查所需 Secrets 是否齐备，写入 `SIGNING_ENABLED=yes|no`。
- `Import Windows code signing certificate`（仅 Windows 且已配置时）：把 base64 的 PFX 还原到 `RUNNER_TEMP`、导入 `Cert:\CurrentUser\My`、立刻删除临时文件，并生成仓库根的 `ci-signing.json`，内容为 Tauri 的 `bundle.windows` 签名参数（`certificateThumbprint` / `digestAlgorithm=SHA256` / `timestampUrl` / `tsp=true`）。
- 两条互斥的构建步骤：
  - 未配置签名 → `Build installers and publish GitHub Release`，与改造前完全一致；
  - 已配置签名 → `Build signed installers and publish GitHub Release`，Windows 通过 `--config ci-signing.json` 注入签名参数，macOS 透传 `APPLE_*` 环境变量。

Tauri 侧的判定（已核对 `tauri-bundler` 源码）：`bundle.windows` 中配置了 `certificateThumbprint` 或 `signCommand` 才会触发签名，签名调用 `signtool sign /fd <digest> /sha1 <thumbprint> /d <productName>`，`tsp=true` 时改用 RFC3161 的 `/tr <url> /td <digest>`。所以**不要把证书提交进仓库**——没配置就等于未签名，配置了才生效。

### 需要配置的 Secrets / Variables

| 名称 | 用途 | 平台 |
| --- | --- | --- |
| `WINDOWS_PFX_BASE64` | 整个 PFX 的 base64 | Windows |
| `WINDOWS_PFX_PASSWORD` | PFX 口令 | Windows |
| `WINDOWS_TIMESTAMP_URL`（Variables，可选） | RFC3161 时间戳服务，缺省 `http://timestamp.digicert.com` | Windows |
| `APPLE_CERTIFICATE` | Developer ID `.p12` 的 base64 | macOS |
| `APPLE_CERTIFICATE_PASSWORD` | `.p12` 口令 | macOS |
| `APPLE_SIGNING_IDENTITY`（可选） | 签名身份名，缺省由证书推断 | macOS |
| `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` | 公证账号（`APPLE_PASSWORD` 用 app-specific password） | macOS |

macOS 的判定条件是上述 5 项齐备才启用签名构建，避免产出「已签名但未公证」这种仍然会被 Gatekeeper 拦下的中间状态。

> SignPath 路线不走这条：它的签名步骤在构建之后、发布之前，需要把 Release 改为草稿、签名后覆盖上传再发布。真要接入时再改，本文记录结论即可。

## 5. 发版后如何核验（不要只看 Actions 绿灯）

```powershell
# Windows，安装包下载到本机后
Get-AuthenticodeSignature .\buffTerm_1.4.8_x64-setup.exe | Format-List Status,SignerCertificate
signtool verify /pa /v .\buffTerm_1.4.8_x64-setup.exe
```

```bash
# macOS
codesign --verify --deep --strict --verbose=2 /Applications/buffTerm.app
spctl -a -vv -t install /Applications/buffTerm.app
stapler validate /Applications/buffTerm.app   # 公证票据是否已钉上
```

未签名状态下这两条必然失败，属预期；接入证书后应作为每次发版的固定核验项。

## 6. 面向用户的说明位点

改动文案时这三处必须同步，中英双语成对维护：

- `README.md` / `README.en.md`：`## 📥 下载` 下的「首次安装说明 / First launch notes」。
- 官网 `index.html` / `en/index.html`：快速开始第 1 步、下载区 `cta-note`、FAQ「首次安装被系统拦截怎么办？」（FAQ 同时存在于页面 `<details>` 与 `FAQPage` 结构化数据两处）。
- 站点文件：`buff-term-site` 仓库，约定见其 README。

签名正式接入后，需要把这些位置的「暂未签名/未公证」改为实际状态，并递增 `js/script.js` 的缓存键。
